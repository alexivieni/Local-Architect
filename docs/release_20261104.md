**Evidence tier.** This page was written from `git status`, `git log` and the files themselves. **No suite was run while writing it**:
every "checks" line below says what a suite *claims* to prove (its own docstring), not that it passed. The reviewer's run of
`selftest --suite full` is what turns these into facts.

### Changed modules

  speed and health, `route_of` with fallback (next machine, then this computer). Only machines the person added are contacted.
- `arch_fleet.py`: agent kind `local_agent`; local kinds run one at a time on the graphics card.
- `arch_hw.py`: `drive_roles` refuses drives slower than `SLOWEST_USEFUL_MB_S` (2 MB/s).
- `arch_templates.py`: imports `arch_templates_extra`.
- `architect_hub.py` + `hub_ui.html`: new endpoints `/api/arch/first_visit`, `/practice`, `/fleet`, `/map`, `/map_sources`,
  `/logbook`, `/library`, `/monitor`, `/token_preview`, `/costs`, `/crew_schedule`, `/flow_save`, `/blueprint_kit`, `/code_health`,
  `/apply_recommended`, `/queue`, `/undo`, `/events/stream`; the first-visit guided path (a practice bug-fix project under the data
  folder), the agents' workspace pages (Fleet, Map, Logbook, Library, Monitor), Blueprints, the design-system page, the calm layer and
  the hub speed fixes (no polling in a hidden tab, no stacked refreshes, recorder samples reused).

### New suites and where they run

Every new `arch_selftest_*.py` is now in `selftest --suite full` (and `all`). Fifteen were missing from the list and were added today in
`architect.py::_run_suites`: `augment`, `broker`, `design`, `firstvisit`, `harness`, `hubperf`, `iterate`, `localagent`, `mesh`,
`placement`, `redact`, `routelearn`, `templates_extra`, `why`, `workspace`. Each is guarded so a suite that stops with `SystemExit`
or an assertion counts as a failure without hiding the rest. Two needed adapters: `hubperf` has no `run()` (its checks are `backend()`
and `ui()`), and `routelearn`'s `run()` is a fixture helper, so its `main()` is called.

Standalone checks that are not selftest suites (run them by hand):

```
python evals/families/distributed.py --check
python evals/families/harness.py --check
python tools/hybrid_bench.py --selftest
python tools/check_overnight.py
```

## 3. Known limits

- **Library-only for now**: `arch_broker`, `arch_routelearn`, `arch_augment`, `arch_placement`, `arch_why` and `arch_redact` are not
  called by the router, the engine, the dataset export or the hub yet; each works on its own and through its suite. Wiring (router
  hint from `suggest_for`, `scrub` in `arch_dataset`/`arch_learn`, Why in the Console) is the next step.
- `hubcalm` and `workspace` check the page's JavaScript with `node --check`; without node that one check reports COULD NOT RUN.
- `arch_selftest_hubperf.py`, `workspace`, `firstvisit` and `routelearn` stop on the first failed check instead of counting failures,
  so a failure there reports one check, not a total.
- The README's check count ("about 850") is stale; update it from the reviewer's full run.
- Still open from the 2026-11-03 review (CLAUDE.md): the escalation fallback ignores `role_hosts`; `arch_server.plan` sizes the KV cache
  as quantised even when the build lacks the cache flags; `flows/bugfix.yaml` does not mirror the read-only-tests rule.
- `MANIFEST.sha256` predates every file above, so `self-verify` will list them as unlisted/modified until `self-verify --write`.
- The hybrid benchmark's Claude modes and the overnight `--with-claude` option spend real money when run by hand; neither runs in any
  suite (`arch_cloud.allowed()` is false under eval and selftest).

## 4. Finishing the release (reviewer, in this order)

Run with the Python that has pytest (on this laptop `py -3.12`), after every other agent on today's job has finished editing:

```
py -3.12 architect.py flows --validate
py -3.12 architect.py selftest --suite full          # must exit 0; note the new total for the README
py -3.12 evals/families/distributed.py --check
py -3.12 evals/families/harness.py --check
py -3.12 tools/hybrid_bench.py --selftest
py -3.12 tools/check_overnight.py
py -3.12 architect.py eval --fake                    # plumbing: the new families must not change the existing baselines
py -3.12 architect.py self-verify                    # expect today's files as unlisted/modified (nothing else)
py -3.12 architect.py self-verify --write            # record the verified state in MANIFEST.sha256
py -3.12 architect.py dist --profile gpu6 --zip      # build the offline installer (app only)
py -3.12 architect.py dist --verify ../architect-gpu6-installer   # the folder it printed (default: next to the app folder)
```

Then update the README check count, and commit (code, docs, `MANIFEST.sha256`) only if every line above passed. A suite line that says
COULD NOT RUN is reported as such, not as a pass.
