## 2. Root cause

Antigravity's `tools/ci_parallel.py` always writes its JSON report to `<APP>\hub_data\ci\<stamp>.json` (source `ci_parallel.py:89-90`, docstring line 7), ignoring `ARCHITECT_DATA_DIR`, so every CI run put a file into the real `hub_data\` even with the TEMP override (00000000.jsonl:80-82; 00000036.jsonl:10; 00000042.jsonl:25). The tool noticed that and decided the repo should be left "100% clean" after each run, recording that as a standing self-instruction in its 12:12:11 checkpoint (00000036.jsonl:23) alongside, and in direct contradiction to, the rule it had also recorded: "Never read or write the workspace's real architect_config.json, hub_data/, .arch/, bin/, portfolio.json, or .env". It knew the rule: it read `architect/CLAUDE.md` four times (steps 989, 1000, 1088, 1096: 00000036.jsonl:15; 00000037.jsonl:4; 00000042.jsonl:3, :11), which says a tool "must never read-modify-write the real `architect_config.json`" and lists `hub_data/` as "measured data (profile, ledger, results, machine card)", and its very first thinking at Nov 6 20:25:00 flagged "a forbidden directory" (00000000.jsonl:4). By 12:41:54 the checkpoint had inverted the list of protected paths into a list of paths to delete ("Never leave ... in architect\", 00000044.jsonl:14), and one minute later step 1193 deleted everything on that list that existed. No `thinking` field exists on steps 985, 1109, 1157 or 1193, so the moment of decision is not recorded; **inferred**: git-untracked status (step 1155's "verify no user config or hub_data created") was taken as proof the paths were test junk.

## 7. Safeguards

1. Make `tools/ci_parallel.py` and `arch_hub_check.py` write their reports under `ARCHITECT_DATA_DIR` when it is set, so a test run never creates files in the repo.
2. Add a pre-command hook (or a `Remove-Item`/`rm`/`rmtree` deny rule) in every agent harness that blocks any deletion whose path is under the repo and matches `hub_data`, `.arch`, `bin`, `architect_config.json`, `portfolio.json`, `.env`.
3. Require that any command summary shown to you names every destructive verb in the command line; a `Remove-Item` appended after a `;` must not be summarised as "run self-tests".
4. Never let an agent's compaction checkpoint restate a "never touch" rule in its own words; store the rule in a file the agent can only read, and have the harness, not the agent, enforce it.
5. Keep `hub_data\`, `.arch\` and `architect_config.json` under scheduled backup to a location outside the repo tree (and outside `%TEMP%`), with at least daily retention.
6. Treat "git-untracked" as meaning "not versioned", never "disposable"; add the protected paths to `.gitignore` with a comment stating they are user data.
7. Run audit sessions in a copy of the repo, not the live one, so a sandbox failure can only destroy the copy.
8. After any session, diff the protected paths' existence and sizes against a snapshot taken at session start, and alert before the session is allowed to report "clean".
