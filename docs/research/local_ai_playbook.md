# Local AI playbook: the rules `arch_swap` checks

Evidence tiers (CLAUDE.md order): **[M]** measured on this machine > **[B]** vendor card / llama.cpp docs / well-replicated benchmark >
**[C]** community practice. `arch_swap.lint(cfg)` checks the current settings against these rules; `arch_swap.plan()` applies the
per-model ones to every option. Each rule id below is the `rule` field of a lint finding.

| rule | the rule | why | evidence |
|---|---|---|---|
| `worker_on_card` | The worker runs 100% on the card, or it is not the worker. | It makes most calls; a dense model with layers in RAM is bound by RAM bandwidth (19.5 GB/s here vs 158 on the card): 3-10x slower per token. | [M] bandwidth.json; qwen3-14b split measured 2.3-2.8 tok/s vs 8B on card 55+ |
| `code_quant` | Q4_K_M or better for code; never Q2/IQ2 for code; Q3/IQ3 only with a measured pass. | Low-bit quants lose exact-token fidelity first, and edits must reproduce lines exactly. | [B] llama.cpp quant perplexity tables; [C] community coding reports |
| (plan) | The builder is at least ~4B effective. | Sub-4B models fail edit formats often enough that their speed does not pay. | [C]; measure with `swap --trial` |
| `kv_q8` | KV cache at q8_0 by default; f16 only when there is room. | Halves cache memory at near-zero quality cost with flash attention. | [B] llama.cpp KV-quant PR measurements |
| `ctx_per_role` | Router ~4k, planner/reviewer ~8k, builder the full window the worker server holds. | Window size is KV memory and prompt time; a planner rarely needs more than the plan + interface. | [B] KV arithmetic; [M] served windows in `server plan` |
| `moe_cpu_ollama` | A MoE heavy model goes beside the worker with only its experts in RAM (`--n-cpu-moe`), never CPU-only via Ollama while our worker holds the card. | Attention + shared weights on the card, few experts read per token from RAM. CPU-only reads everything from RAM. | [M] heavy beside the worker 14-16 tok/s vs 8.2 tok/s via Ollama |
| `thinking` | Thinking off for code edits, on for plan/review. | Thinking costs time and drifts the edit format; it helps decomposition and judging. | [B] Qwen3 card (thinking/non-thinking modes); [C] |
| `draft` | A draft only with the worker's identical tokenizer (model, pre-tokenizer, vocab) and <= 1/3 its size; else n-gram or MTP. | A draft must propose exactly the tokens the worker would; a big draft costs more than it saves. | [B] llama.cpp speculative docs; [M] qwen3:0.6b draft 66-125 tok/s vs n-gram 306-343 on edits |
| `swap_churn` | Avoid per-call model swaps; a role model outside the tiers swaps on every call. | One load costs ~5-15 s on this machine class. | [M] restart cost 5-8 s, load_s 24 s for the 13 GB MoE |
| `vram_headroom` | Leave >= 300 MiB of graphics memory free. | The driver pages to shared memory and decode collapses without warning. | [C]; [M] desktop share measured as desk_gb |
| `ram_headroom` | Leave >= 4 GB of RAM after models, Windows (~6 GB) and Docker/WSL. | Windows pages to disk and every tier crawls. Plan around Docker/WSL, never change it. | [C]; [M] `arch_hw.vm_memory` |

## Cache and load rules (`swap --lint`, every one says whether it is on)
`arch_swap.cache_checks()` reports each of these as ON or OFF under the current settings; `swap --lint --cache` lists all of them, `swap --lint` only the
ones that are off. Evidence tier first in the evidence column; `verify` is the step that proves it on this machine (`tools/verify_machine.py --gpu` is the
live layer: it starts servers, measures and always cleans up). A rule whose evidence says "not yet measured" is advice, not a result.

| rule | the rule | why | evidence | how to verify |
|---|---|---|---|---|
| `cache_reuse` | Reuse matching prompt chunks (server.cache_reuse > 0). | A retry changes a middle part of the prompt (the feedback); with chunk reuse the model re-reads only what is new instead of everything after the change. | [B] llama.cpp --cache-reuse; effect here not yet measured | py -3.12 tools/verify_machine.py --gpu (step 'prefix reuse cache_n/prompt_n': cache_n should be most of the prompt on the second call) |
| `cache_prewarm` | Pre-warm role prompts (server.prewarm = on). | Each role's fixed instructions are read once at start and saved, so its first call of a run skips them. Opt-in: it costs disk (server.prewarm_gb) and a little start time. | [E] prompt-time arithmetic; not yet measured here | py -3.12 tools/verify_machine.py --gpu (steps 'slot save -> restore' and 'prefix reuse cache_n/prompt_n') |
| `cache_static_lookup` | Speculation from your code (server.static_lookup = on). | Draft tokens come from names in your own project, so edits that repeat existing code are accepted in long runs. N-gram speculation itself is the measured win. | [M] n-gram speculation on edits 56 -> 306-343 tok/s; the project lookup on top is [C] | py -3.12 tools/verify_machine.py --gpu (step 'n-gram speculation on vs off') |
| `cache_batch` | Prompt batch sizes sane (server.ubatch 128-1024, server.batch >= ubatch). | Prompt tokens are read in these chunks: too small reads long prompts slowly, too large takes graphics memory the worker needs. | [B] llama.cpp -b/-ub docs; sweet spot on this card not yet measured | py -3.12 tools/verify_machine.py --gpu (step 'decode tok/s'); `architect.py server plan` shows the graphics memory left |
| `cache_threads` | CPU threads follow the performance cores (-t = performance cores, -tb = all cores; no model_overrides.num_thread above the core count). | E-cores slow every step of a CPU-bound tier; too many threads fight Windows and the tests. | [M] machine audit 2026-11-03 (11 threads on a 4P+4E laptop was worse); exact gain not re-measured | py -3.12 tools/verify_machine.py --gpu (step 'decode tok/s') before and after a change |
| `load_mode` | Big MoE models pinned and read whole (server.mlock and server.no_mmap not 'off'). | The experts live in RAM; without pinning Windows moves them to disk under pressure and decode stalls, and demand paging makes the first tokens slow. | [B] llama.cpp --mlock/--no-mmap docs; [M] heavy beside the worker 14-16 tok/s with experts in RAM | py -3.12 tools/verify_machine.py --gpu (steps 'server start -> health' and 'decode tok/s' on the heavy tier) |
| `cache_kv_heavy` | The planner's cache at q4_0 when it stays beside the worker (server.kv_heavy = auto or q4_0). | A quarter of the memory of f16 on a card the worker shares. Fine for plan/review; never for code, which is why only the heavy tier gets it. | [B] llama.cpp KV-quant measurements (small quality cost); not measured here | `architect.py server plan` (heavy KV line) and a plan-quality eval: `architect.py eval --quick` |
| `cache_slot_persist` | Prompt memory kept between runs (server.slot_persist = auto). | The project's fixed prompt start is saved after the first call and restored by the next run, so it starts warm. | [M] slot save/restore is a verify_machine step; gain per run not yet measured | py -3.12 tools/verify_machine.py --gpu (step 'slot save -> restore') |
| `cache_stable_context` | Same project context on every retry of a step (behavior.stable_context). | The server can only reuse a prefix that is byte-identical; re-ranking files per try changes the start and throws the cache away. | [M] arch_selftest_promptprefix (retry templates keep the stable part first); live reuse via cache_n | py -3.12 tools/verify_machine.py --gpu (step 'prefix reuse cache_n/prompt_n') |
| `cache_tool_cache` | Tool results cached inside a run (behavior.tool_cache = on). | Repeated read/ls/grep on unchanged files cost nothing; any edit clears the affected entries. | [E] code-side, no model call saved or added; correctness proved by selftest | `py -3.12 arch_selftest.py` (tools suite); `architect.py caches` shows hits |
| `cache_squad_prefix` | Crew agents share one identical first block and get digests (squad.shared_prefix and squad.digest = on). | Agents of one phase reuse each other's cached prompt; later phases read a short digest, not a transcript. | [M] Claude lead 98% prompt-cache hit with the shared header; 8-finding result ~5,000 chars reaches the next phase as <= 800 | arch_selftest_squad.py; `architect.py caches` (Agent steps layer) |
| `cache_rank` | File ranking remembered between context builds (behavior.rank_cache = on). | Only files whose size or time changed are re-read when the context is built. | [E] code-side; correctness proved by selftest | `architect.py caches` (rank layer); arch_selftest_cacheplus.py |
| `cache_incremental_index` | Retrieval index updated incrementally (always: changed files only). | Only changed or new files are re-chunked, so the index never costs a full re-read of the project. | [E] by design (arch_index); retrieval quality measured by bench-retrieval | `architect.py bench-retrieval` |
| `cache_ollama_keep_alive` | Ollama keeps a model loaded for at most ~2 minutes (server.ollama_keep_alive, default 60s). | A model Ollama still holds when the next run starts takes RAM or graphics memory the servers need; the heavy MoE alone is ~20 GB in RAM. | [M] heavy MoE in RAM ~20 GB; Ollama had put 28% of it on the card and starved the worker | `architect.py status` after a run: the model should be gone; hub_data/live.log RAM column |
| `cache_heavy_beside` | The MoE heavy model stays loaded beside the worker (server.heavy_beside != off). | Switching to the planner costs about 1 s instead of a 5-15 s load per call. | [M] heavy beside the worker 14-16 tok/s, switching in about 1 s | py -3.12 tools/verify_machine.py --gpu (step 'server start -> health'); `py -3.12 after_upgrade.py` |
| `fast_lane_vs_heavy` | Fast lane (server.fast_lane) and the heavy planner: choose knowingly. | The fast lane gives the worker the whole card, so the heavy model is loaded only when a call needs it: every run that plans pays a load (5-8 s restart here) and the heavy server does not stay resident. | [M] restart cost 5-8 s; fast-lane window arithmetic from arch_selftest_fastlane | py -3.12 tools/verify_machine.py --gpu; compare plan time of `architect.py run` with fast_lane off and on |
| `cache_cloud_ttl` | Claude prompt-cache lifetime chosen by the app (online.cloud_cache_ttl = auto). | A 1-hour cache write costs 2x, a 5-minute one 1.25x; auto picks per use so a long shared prefix is not re-written needlessly. Only matters when Claude is enabled. | [B] Anthropic prompt-caching pricing; [M] 6-call Council answer $0.27 -> $0.18 with a shared prefix | arch_selftest_cloud.py (no live call); `architect.py costs` |
| `cache_readonly_model` | Read-only Claude agents on the cheaper model (online.readonly_model = auto). | An agent that cannot write does not need the strongest model. | [B] model price list (arch_cloud.PRICES); no quality measurement here | arch_selftest_cloud.py; `architect.py orchestration` shows the model per agent |
| `cache_batch_jobs` | Non-urgent Claude jobs through the Batch API (online.batch_jobs). | Half price, results later; only for work nobody waits on. Off by default and gated by the Claude allowed() check. | [B] Anthropic Batch API pricing | arch_selftest_cloud.py |
| `per_call_swap` | An agent on the heavy tier that runs more than once per run while heavy is not resident beside the worker. | Each of its calls can load the 13 GB model: 5-15 s per call on this card. Planners run once; repeat jobs (verifiers, panels) belong on the worker. | [M] restart cost 5-8 s, load_s 24 s for the 13 GB MoE | py -3.12 tools/verify_machine.py --gpu (step 'server start -> health'); `architect.py crew <workflow> --fake` then read 'Run economics' |

## How a swap is decided
1. `swap --plan --tier T | --job J`: per installed model, placement math (layers on card, KV at q8_0 for the role's window, MoE
   expert offload and its RAM, VRAM/RAM headroom), decode tok/s (bandwidth model [E] against the passport's measured figure [M]; the
   lower is used, because the passport does not record the placement it was measured at), measured C / pass rate with Wilson CI from
   `select` results, the family prior, speculation fit, recommended settings. Score = measured C when >= 8 decided tasks exist,
   else a prior-adjusted estimate (labelled on every option).
2. `swap --trial T MODEL`: edit-format probe + 3 tasks of the job + decode speed, under the heavy-job lock. pass = format ok and
   >= 2/3 passed and speed over the target's floor; not_sure otherwise unless nothing passed (fail).
3. `swap --apply T MODEL --yes`: refused without a passed trial in the last 7 days (unless `--force`, recorded), writes with an
   undo record; `swap --undo` restores.

## New downloads
`swap --new` (`arch_swap.on_new_models`): every installed model without a passport gets one built, its family identified (`arch_modelknow`),
and `plan()` run for every job. One suggestion record per model is appended to `<data>/swap/suggestions.jsonl` (`applied: false`). It never applies: a
suggestion names the `swap --trial job:J MODEL` that has to pass first.
