# Evaluation protocol

How Architect measures a model, a harness change, or an orthogonalization edit. Everything below is code in this repository
(`arch_eval.py`, `evals/families/*.py`, `arch_triage.py`, `arch_costmodel.py`, `tools/h1_analysis.py`). Numbers are as of
2026-11-05.

## 1. Tasks

Each task is generated by a family in `evals/families/`. Families take a seed, so the same task can be drawn again and a new seed
gives new instances. The default set (`python architect.py eval`) holds **121 tasks in 19 families**: bugfix 17, route 12,
refusal 10, and 4 to 6 each for build, feature, test, refactor, review, hunt, secure, config, network, cicd, purge, design,
planjson and e2e (whole-project builds). There are also 105 training tasks: 65 distributed-systems and 40 harness-building, each
family drawing one task by default and up to 65/40 with `--n`. Of those, 21 are held out (tag `holdout`).

Every task carries:
- a **goal** in plain words, stating its interface when it has one ("Public interface, exactly: ...");
- a **fixture** (files the project starts with);
- a **budget** (calls, tokens, seconds);
- **judges**: checks that decide the verdict, run by code after the run, never shown to the model;
- a **reference solution** and, for most families, a deliberately **wrong solution**.

## 2. Judges and verdicts

The judges are code (14 types): `python_assert` (a hidden behaviour check), `tests_pass` (the project's own tests), `file_exists`,
`file_contains`, `file_lacks`, `files_unchanged`, `functions_present`, `no_shrink`, `scanner_zero`, `ci_no_blocking`,
`docs_structure`, `json_shape`, `route_equals` and `no_refusal`. Each answers True, False, or "could not run". The verdict is:

- **pass**: every judge ran and passed;
- **fail**: a judge ran and failed;
- **not sure**: a judge could not run. This never counts as a pass, and is never used as a training label.

`no_refusal` reads the task's own trace. A run is refused when at least one reply declines and no reply contains any work.

## 3. Proving the instrument

A benchmark is only as good as its judges, so every family is proven before it is trusted:
- the **oracle** (`eval --fake`, a scripted model that answers with each task's reference solution) must pass every task end to end,
  through the real flows;
- the **wrong solutions** must fail at least one judge (`arch_selftest_eval`, and `refusal.py --check` for the refusal family);
- a **replay** of a real failure through the flow shows that a harness fix changes the outcome, for example the interface wiring
  (`arch_selftest_wiring`).

## 4. Running live

`python architect.py eval [--tags ...] [--n N] [--seed S] --label NAME` runs tasks one at a time on this machine's models. It holds
the machine's job lock, so nothing else heavy runs alongside. During an eval:
- the reply caches are off;
- nothing is learned from the run (the ledger and few-shot examples);
- learned reply budgets and retry stopping are off, so the fixed policy is measured;
- each task runs in a throwaway folder, and its trace is kept: in `<data>/evals/runs/train` for training tasks that are not held
  out, and in `.../bench` for everything else.

## 5. Data separation

Only the `train` bucket can become training data (`arch_dataset`). Also excluded:
- benchmark and held-out tasks;
- replies written by Claude;
- tries that passed only with the harness's interface wiring (traced `assist`);
- replies replayed from a cache;
- calls whose checks could not run.

So no model is ever trained on the benchmark that judges it.

## 6. Measures

- **Pass rate** per flow and per task family, and the not-sure rate.
- **C**, the time per accepted change (Eq. 16-17): seconds spent divided by tasks passed, per model and task family
  (`architect.py cost`, Models > Cost map). "How sure" for the cheapest model per family comes from Thompson draws over
  Beta(passes + 1, fails + 1).
- **Refusal rate** on the safe-but-triggering refusal family.
- **Failure families** (`arch_triage`, no model call): environment, refusal, wiring, tests, timeout, behaviour.
- **Prefix reuse ρ** and per-try pass rates from the kept traces.
- **Model provenance** per run: quantization, weight edit, base model, licence.

## 7. The regression gate

`eval --compare BASELINE` exits 1 when any flow regresses:
- pass rate down by more than 5 points;
- median tokens up by more than 25%;
- 95th-percentile seconds up by more than 40%;
- refusal rate up by more than 5 points.

`promote-model` and `self-improve` use the same gate; self-edits must also keep at least as many checks (Eq. 24).

## 8. H1 (orthogonalization), paired

`tools/h1_analysis.py` pairs each task by id and seed across the two workers (abliterated vs base, everything else equal), leaves
"not sure" pairs out, and reports the pass-rate and refusal-rate differences with bootstrap 95% intervals, plus the discordant pairs
(the counts a McNemar test uses). The deployment gate (§2.4) keeps the edit only if the pass-rate interval's lower end stays above -5
points and refusals fall or stay at zero.

## 9. Known limits

- Few tasks per family by default; three seeds for H1. Conclusions need more seeds and the larger `--n`.
- The models' own sampling is not seeded, so repeated tasks also measure sampling noise.
- Timings depend on placement (the 2026-11-05 finding: Ollama holding part of the card cut the worker to 9 of 36 layers). The run
  logs record the worker's layer count; compare timings only under the same placement.
- The task families are synthetic and Python-only. Repository-level tasks with hidden tests are specified in the report (§9) but
  not built.
