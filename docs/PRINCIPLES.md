# Orchestration principles

What made the Claude lead cheap and reliable (2026-11-05), applied to the local crew (`arch_squad.py`, `architect.py crew`).
Evidence below is what happened here; numbers not measured are not given. The lessons table at the end is data
(`data/lessons.json`, checked by `py -3.12 arch_lessons.py`).

## 1. Summaries, not transcripts
The next phase gets a structured digest of an agent's result: short scalar fields (verdict), a summary cut to fit, the file list, findings
one line each, at most 800 characters (`squad.digest_chars`). The full result stays in the agent record and the journal.
- Evidence: the Claude lead ran on shared cached headers and digests with a 98% prompt-cache hit. Local fake run in
  `arch_selftest_squad.principles_checks`: an 8-finding, 40-file result of ~8,000+ characters reaches the next agent as <=800 (the
  test prints the figures and the tokens saved, about 4 chars per token).
- Enforced: `arch_squad.digest`, applied in `Crew.agent` to every `context: inherit` agent; `rec["context_chars"]` records raw vs shown;
  `squad.digest = off` turns it off. `Crew.shared_header` is the byte-identical cacheable prefix.

## 2. Code over agents
A deterministic step is code, not a model. `code:` phases (with `with:` arguments) have `run_suites` (parallel, each suite in its own
throwaway ARCHITECT_HOME / DATA_DIR, like `tools/ci_parallel.py`), `diff_stats` (added/removed lines, line endings ignored),
`dedupe_findings`, `count_json`, `validate_json`, `collect`. Paths stay inside the project; no shell.
- Evidence: the lead counted, diffed and ran suites in scripts; a model asked to do arithmetic or run tests is slower and wrong more often.
- Line-ending lesson: the same change measured 23k changed lines with CRLF/LF churn and 2.2k without, so `diff_stats` ignores endings.
- Config-wipe lesson: two test suites once overwrote `architect_config.json`; `run_suites` and every runner give each suite its own home.
- Enforced: `arch_squad.run_suites`, `diff_stats`, `CODE_STEPS`.

## 3. Tiered models by job
Mechanical steps (summarise, route) run on the router tier (smallest model), building on the worker, design and verification on heavy.
These are defaults in `agents/*.md` (`model:`), mapped in `arch_roleprofile.JOB_TIER` / `AGENT_JOB`. A model the person set always wins:
a `roles.<role>` assignment (`arch_squad.local_model`), `--set agent.model=...`, or a settings override. Claude models stay refused.
- Enforced: `arch_roleprofile.agent_tier`; checked: every shipped agent's `model:` equals its job's tier.

## 4. Owned files and adversarial verify
Every agent owns named files (or none); two running agents never share one (`OwnershipClash`, raised before anything starts). A workflow
that can write ends with read-only verifiers (agents with `writes: false`: read, grep, run_tests).
- Evidence: verifiers caught a symlink / zip-slip hole, telemetry that could leak secrets, and a stale resume that replayed old results.
- Enforced: `arch_squad.shape_problems` (shipped workflows are checked; the three mined `learned_*` workflows that ended on a builder got
  a final verify panel), `arch_squad.ownership_problems`. Never `git stash`, checkout or reset in a shared tree.

## 5. Fresh context per task
A run never carries another run's conversation: a `Crew` starts empty, an agent with `context: fresh` is shown no earlier result, and an
`inherit` agent sees only the digest, capped at half its role's prompt window (`arch_roleprofile.context_chars`, `arch_squad.context_cap`;
`squad.role_context = off` lifts it). Resume replays identical steps only.
- Evidence: planner context 12k -> 8k and router 8k -> 4k lost nothing measured; the router's window must never size project context.
- Checked: a second run's briefs contain nothing of the first (`principles_checks`).
